## 1. 接口规范总则

### 1.1 REST 与版本

- 基础路径：业务接口 `/api/v1`，开放平台 `/openapi/v1`，管理接口 `/api/v1/admin/**`。
- 资源命名小写复数（`/spaces`、`/documents`、`/conversations`、`/api-keys`）；方法语义 `GET` 查询 / `POST` 创建或动作 / `PUT` 全量更新 / `PATCH` 部分更新 / `DELETE` 逻辑删除。
- 时间格式 ISO 8601（`2026-10-29T10:00:00+08:00`），统一 `UTC` 存储、按租户时区回显；URL 中不出现动词（动作用子资源表达，如 `/reindex`、`/approve`）。

### 1.2 统一响应结构

成功：
```json
{ "code": 0, "message": "ok", "data": {}, "trace_id": "trc_9f8a7b6c5d4e", "request_id": "req_01HZX9K2" }
```
失败：
```json
{ "code": 40401, "message": "resource not found", "data": null, "trace_id": "trc_9f8a7b6c5d4e", "request_id": "req_01HZX9K2" }
```
列表响应 `data` 统一为 `{ "items": [], "page": { "cursor": "next-page-token", "has_more": true, "limit": 20 } }`。

### 1.3 错误码规范

| code | HTTP | 含义 | 阶段 |
|---|---|---|---|
| 0 | 200/201 | 成功 | MVP |
| 40001 | 400 | 请求参数非法 | MVP |
| 40101 / 40102 | 401 | 未认证/令牌失效 / API Key 无效或过期 | MVP |
| 40301 / 40302 / 40303 | 403 | 无权限 / 跨租户越权 / 需人工审批 | MVP/V1 |
| 40401 | 404 | 资源不存在 | MVP |
| 40901 / 40902 | 409 | 资源冲突（重复上传等）/ 版本冲突（乐观锁） | MVP/V1 |
| 42201 / 42202 | 422 | 语义校验失败 / 文档解析或内容不合规 | MVP |
| 42901 / 42902 | 429 | 触发限流 / 配额不足 | MVP/V1 |
| 50001 | 500 | 服务内部错误 | MVP |
| 50301 | 503 | 依赖服务不可用（LLM/MCP/向量库） | MVP |

### 1.4 鉴权方式

| 方式 | Header | 场景 |
|---|---|---|
| JWT Bearer | `Authorization: Bearer <jwt>` | Web / SSO 用户态 |
| API Key | `Authorization: Bearer <api_key>` 或 `X-API-Key: <key>` | OpenAPI 开发者 |
| MCP Token | MCP 协议头 + 平台侧 `tool_grant` | 工具调用 |

- JWT / API Key 统一经 Spring Security 6 `SecurityFilterChain` 校验，认证主体封装为 `AuthenticatedPrincipal`（含 `tenant_id`、`user_id`、`roles`、`api_key_id`）。
- 每请求生成 `request_id`，写入 MDC 并透传 Langfuse / Micrometer trace。

### 1.5 分页

- 游标分页 `?cursor=<token>&limit=<n>`，`limit` 上限 100、默认 20；返回 `page.cursor` 与 `page.has_more`。
- 游标由 `Base64(排序键 + 时间戳)` 生成，禁止 `offset` 深翻页；时间倒序场景按 `(created_at DESC, id DESC)` 稳定排序。

### 1.6 幂等

- 写操作支持 `Idempotency-Key: <UUID>` Header；服务端以 `(tenant_id, key)` 唯一索引缓存首次结果 24h，重复请求回放首次响应。
- 强制幂等：文档上传、分片合并、API Key 创建、Webhook 注册、任务提交。
- 乐观锁：更新类接口支持 `If-Match: <version>`，不匹配返回 `40902`。

## 3. 关键接口详细定义

### 3.1 文档上传

`POST /api/v1/ingestion/upload`（`multipart/form-data`）｜ 鉴权 JWT(`kb_admin`) ｜ 幂等 `Idempotency-Key` 强制

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| space_id | UUID | 是 | 目标空间 |
| file | File | 是 | 文档文件（≤200MB） |
| title | String | 否 | 标题（默认取文件名） |
| tags | String[] | 否 | 标签（需存在且当前用户可见） |
| visibility | String | 否 | `inherit`/`public`/`private`，默认 `inherit` |
| idempotency_key | String | 是 | 幂等键（Header 或 body） |
请求示例（以 `multipart/form-data` 提交：`file` 为二进制文件字段，其余为普通表单字段；下例为字段结构示意，`idempotency_key` 亦可置于 Header）：
```json
{ "space_id": "b3f0c1e2-8d4a-4f10-9c2b-1a2b3c4d5e6f", "title": "员工差旅报销管理办法", "tags": ["hr", "finance"], "visibility": "inherit", "idempotency_key": "7c1e9a2b-4d5e-4f60-8a7b-1c2d3e4f5a6b" }
```
响应示例：
```json
{ "code": 0, "message": "ok", "data": { "document_id": "d1a2b3c4-5e6f-4a70-8b9c-0d1e2f3a4b5c", "status": "pending", "duplicated": false, "version_no": 1, "task_id": "job_20261029_000123" }, "trace_id": "trc_9f8a7b6c5d4e" }
```
错误码：`40001`（文件超限/格式不支持）、`40101`、`40301`、`40901`（重复上传）、`42902`（租户文档数超限）。

### 3.2 文档状态查询

`GET /api/v1/documents/{id}/status` ｜ 鉴权 JWT ｜ Query：`include_chunks`（bool，默认 false）
```json
{ "code": 0, "message": "ok", "data": { "document_id": "d1a2b3c4-...", "status": "indexing", "current_version": 3, "chunk_count": 120, "job": { "job_id": "job_20261029_000123", "stage": "index", "attempt": 1 }, "updated_at": "2026-10-29T10:00:00+08:00" }, "trace_id": "trc_9f8a7b6c5d4e" }
```
错误码：`40101`、`40302`、`40401`。

### 3.3 知识库检索

`POST /api/v1/retrieval/search` ｜ 鉴权 JWT ｜ 服务端强制注入权限过滤条件

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| query | String | 是 | 查询文本（≤4000 字符） |
| space_ids | UUID[] | 否 | 限定空间（空=全部有权限空间） |
| top_k | Int | 否 | 默认 10，上限 50 |
| rerank | Bool | 否 | 默认 true |
| filters | Object | 否 | `{tags:[], document_type:[]}` |
| min_score | Float | 否 | 最低得分阈值（0–1） |
请求示例：
```json
{ "query": "差旅费报销标准是多少", "space_ids": ["b3f0c1e2-8d4a-4f10-9c2b-1a2b3c4d5e6f"], "top_k": 10, "rerank": true, "filters": { "tags": ["finance"] }, "min_score": 0.35 }
```
响应示例：
```json
{ "code": 0, "message": "ok", "data": { "items": [ { "chunk_id": "c8f3a2b1-1111-4a22-9b33-4c5d6e7f8a90", "document_id": "d1a2b3c4-...", "space_id": "b3f0c1e2-...", "heading_path": "第三章 报销标准", "score": 0.92, "snippet": "国内差旅住宿标准：一线城市 500 元/晚……", "citation_id": "Cc8f3a2b1e" } ], "query_id": "q_20261029_88412", "latency_ms": 182, "degraded": false }, "trace_id": "trc_9f8a7b6c5d4e" }
```
错误码：`40001`、`40101`、`40302`、`42901`、`50301`。

### 3.4 发起问答（SSE 流式）

`POST /api/v1/agent/chat` ｜ 鉴权 JWT ｜ `Accept: text/event-stream`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| conversation_id | UUID | 否 | 空则新建会话 |
| query | String | 是 | 用户问题（≤8000 字符） |
| space_ids | UUID[] | 否 | 限定检索空间 |
| model | String | 否 | 指定模型，默认租户配置 |
| stream | Bool | 是 | 固定 true |
| trace | Bool | 否 | 是否返回 `trace_id`，默认 true |
请求示例：
```json
{ "conversation_id": "cv_1234", "query": "帮我总结差旅报销流程", "space_ids": ["b3f0c1e2-8d4a-4f10-9c2b-1a2b3c4d5e6f"], "model": "deepseek-v3", "stream": true, "trace": true }
```
响应（SSE，详见第 4 节）：`meta` → `token`* → `citation`* → `done`（或 `error`）。
错误码：`40001`、`40101`、`40301`、`42901`、`50301`（流式错误以 `error` 事件下发，HTTP 状态仍为 200）。

### 3.5 会话历史

`GET /api/v1/conversations/{id}/messages` ｜ 鉴权 JWT ｜ Query：`limit`（默认 50，上限 200）、`cursor`、`role`（可选）
```json
{ "code": 0, "message": "ok", "data": { "conversation_id": "cv_1234", "items": [ { "message_id": "m_1", "role": "user", "content": "差旅报销标准？", "created_at": "2026-10-29T10:00:00+08:00" }, { "message_id": "m_2", "role": "assistant", "content": "国内差旅住宿标准……", "citations": ["Cc8f3a2b1e"], "created_at": "2026-10-29T10:00:05+08:00" } ], "page": { "cursor": "m2", "has_more": false, "limit": 50 } }, "trace_id": "trc_9f8a7b6c5d4e" }
```
错误码：`40101`、`40302`、`40401`。

### 3.6 反馈提交

`POST /api/v1/messages/{message_id}/feedback` ｜ 鉴权 JWT ｜ 幂等 `Idempotency-Key`（可选）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| rating | Int | 是 | 1–5 |
| comment | String | 否 | 评语（≤2000） |
| reason | String | 否 | `accurate`/`inaccurate`/`no_citation`/`irrelevant` |
| citation_feedback | Object[] | 否 | `[{citation_id, accurate}]` |
请求示例 / 响应示例：
```json
{ "rating": 5, "comment": "引用准确", "reason": "accurate", "citation_feedback": [{ "citation_id": "Cc8f3a2b1e", "accurate": true }] }
```
```json
{ "code": 0, "message": "ok", "data": { "feedback_id": "fb_99", "rating": 5, "created_at": "2026-10-29T10:01:00+08:00" }, "trace_id": "trc_9f8a7b6c5d4e" }
```
错误码：`40001`、`40101`、`40302`、`40401`。

### 3.7 API Key 创建

`POST /openapi/v1/api-keys` ｜ 鉴权 JWT(`developer`/`admin`) ｜ 幂等 `Idempotency-Key` 强制
请求参数：`name`（必填）、`scopes`（如 `["retrieval:read","agent:chat"]`）、`expires_at`（ISO8601，可空）、`allowed_space_ids`（UUID[]，可空）。
请求示例：
```json
{ "name": "bi-export", "scopes": ["retrieval:read", "agent:chat"], "expires_at": "2027-10-29T00:00:00+08:00", "allowed_space_ids": ["b3f0c1e2-8d4a-4f10-9c2b-1a2b3c4d5e6f"] }
```
响应示例：
```json
{ "code": 0, "message": "ok", "data": { "api_key_id": "ak_01", "name": "bi-export", "key_prefix": "zxk_9f8a", "api_key": "zxk_9f8a7b6c...（仅创建时返回一次）", "scopes": ["retrieval:read", "agent:chat"], "expires_at": "2027-10-29T00:00:00+08:00", "created_at": "2026-10-29T10:00:00+08:00" }, "trace_id": "trc_9f8a7b6c5d4e" }
```
错误码：`40001`、`40101`、`40301`、`40901`、`42902`。

### 3.8 工具注册

响应示例：

错误码：`40001`、`40101`、`40301`、`50301`（MCP 端点不可达）。

## 4. SSE 流式问答协议

### 4.1 事件类型

| 事件 | 说明 | `data` 字段 |
|---|---|---|
| `meta` | 会话与路由元信息（连接后首个事件） | `conversation_id`、`message_id`、`intent`、`model`、`trace_id` |
| `token` | 答案增量文本 | `delta`、`index` |
| `citation` | 引用片段（可能在 token 前集中下发） | `citation_id`、`chunk_id`、`document_id`、`snippet`、`score` |
| `tool` | 工具调用事件 | `tool_name`、`status`、`summary`、`duration_ms` |
| `approval` | 需人工审批 | `approval_id`、`tool_name`、`reason` |
| `done` | 结束 | `finish_reason`、`tokens_out`、`citations`、`elapsed_ms` |
| `error` | 错误 | `code`、`message`、`retryable` |

### 4.2 示例事件序列
```
event: meta
data: {"conversation_id":"cv_1234","message_id":"m_2","intent":"knowledge_qa","model":"deepseek-v3","trace_id":"trc_9f8a7b6c5d4e"}

event: token
data: {"delta":"差旅报销","index":0}

event: token
data: {"delta":"流程如下：","index":1}

event: citation
data: {"citation_id":"Cc8f3a2b1e","chunk_id":"c8f3a2b1-1111-4a22-9b33-4c5d6e7f8a90","document_id":"d1a2b3c4-...","snippet":"第三章 报销标准……","score":0.92}

event: tool
data: {"tool_name":"oa_approval_query","status":"success","summary":"查询到 2 条审批记录","duration_ms":210}

event: approval
data: {"approval_id":"ap_1","tool_name":"oa_approval_query","reason":"high-risk"}

event: token
data: {"delta":"……","index":2}

event: done
data: {"finish_reason":"stop","tokens_out":486,"citations":["Cc8f3a2b1e"],"elapsed_ms":2140}
```
### 4.3 约定

- 响应头：`Content-Type: text/event-stream; charset=UTF-8`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`（防 Nginx 缓冲）。
- 心跳：每 15s 发送 `: ping` 注释行，防代理超时断开。
- 客户端断开：通过 `SseEmitter.onCompletion`/`onError`/`onTimeout` 感知，取消生成并记录 `aborted` 审计事件。
- `done` 前必须保证所有 `citation` 已下发；`error` 之后不再发送 `done`。
- 同一会话并发生成需互斥（Redis 分布式锁），后发请求返回 `40901` 或复用进行中的回答。

### 4.4 Spring WebFlux `SseEmitter` 实现要点

- 接口返回 `Flux<ServerSentEvent<String>>`（首选）或 `SseEmitter`；Spring WebFlux 下统一 `Flux<ServerSentEvent<String>>` + `MediaType.TEXT_EVENT_STREAM`。
- 响应式背压：LLM token 流为 `Flux<String>`，经 `onBackpressureBuffer()` 或 `.limitRate(...)` 控制内存上限，防止慢消费打爆堆内存。
- 超时：`SseEmitter(0L)` 表示不限时，但须配合网关与 Netty 配置合理上限（默认 300s，可配置）。
- 禁止阻塞：`SseEmitter` 非阻塞，禁止在其中执行阻塞 JDBC / CPU 密集调用；权限过滤与检索走响应式 R2DBc / pgvector 客户端。
- 优雅关闭：正常 `emitter.complete()`；异常 `emitter.completeWithError(throwable)` 并由全局异常处理器兜底下发 `error` 事件。
- Langfuse 集成：每次问答创建 trace，`meta` 事件下发 `trace_id`，token 增量上报 `generation` span。

## 5. WebSocket 协议

- 路径：`/ws/v1/events`，子协议 `zxkap.v1`，承载于 Spring WebFlux `WebSocketHandler`（Netty）。
- 鉴权：建连时 `?token=<jwt>` 或首帧 `auth`；未认证连接 10s 内未认证即关闭（code `4401`）。
- 帧格式（双向 JSON）：`{ "type": "event", "event": "document_status", "payload": { "document_id": "d1", "status": "ready" } }`

| 方向 | 类型 / 事件 | 说明 |
|---|---|---|
| C→S | `auth` | 建连鉴权（`token`） |
| C→S | `subscribe` | 订阅主题 `{ "topics": ["document_status","task_progress"] }` |
| C→S | `ping` | 心跳 |
| S→C | `auth_ack` | 鉴权结果 |
| S→C | `document_status` | 文档处理状态变更 |
| S→C | `task_progress` | 任务进度 |
| S→C | `agent_node` | Agent 节点流转（LangGraph4j 节点事件） |
| S→C | `approval_request` | 人工审批请求 |
| S→C | `pong` | 心跳应答 |

- 心跳：服务端每 30s 发 `ping`，客户端 60s 无响应则断开。
- 连接数限制：单用户 ≤5 连接，超限返回 `42901` 并关闭。

## 6. MCP 工具接口

| 方法 | 说明 | 方向 |
|---|---|---|
| `initialize` | 握手与能力协商（协议版本、`tools` 能力、`streaming` 能力） | Client→Server |
| `notifications/initialized` | 初始化完成通知 | Client→Server |
| `tools/list` | 工具发现（返回 JSON Schema 与描述） | Client→Server |
| `tools/call` | 工具调用 | Client→Server |
| `notifications/progress` | 流式进度通知（可选） | Server→Client |
| `resources/list` / `resources/read` | 资源发现与读取（V2） | Client→Server |

调用约定：

- 平台侧先做 `tool_grant` 鉴权与配额校验，再经 MCP 网关转发至目标 Server。
- 请求超时默认 30s（按 `risk_level` 调整：`high` 10s），失败重试 1 次（仅幂等工具）。
- 结果标准化为 `{ "ok": true, "data": {}, "error": null, "meta": { "tool_id": "tl_1", "duration_ms": 210, "trace_id": "trc_..." } }`。
- 流式约定：长耗时工具通过 `notifications/progress` 上报 `progressToken`、`progress`、`message`，最终以 `tools/call` 结果帧结束。
- 详细接入设计见 [09-详细设计-RAG与Agent](09-详细设计-RAG与Agent.md) §8。

## 7. 事件与 Webhook

### 7.1 RabbitMQ 事件

| 事件 | Queue | 触发 | 载荷 |
|---|---|---|---|
| `task.completed` | `zxkap.task.completed` | 异步任务完成 | `job_type`、`document_id`、`status`、`attempt` |
| `document.status_changed` | `zxkap.document.status` | 文档状态变更 | `document_id`、`from`、`to`、`tenant_id` |
| `agent.completed` | `zxkap.agent.completed` | 问答完成 | `conversation_id`、`message_id`、`citation_accuracy` |
| `citation.invalid` | `zxkap.citation.invalid` | 引用校验失败 | `message_id`、`citation_id`、`reason` |
| `memory.written` | `zxkap.memory.written` | 长期记忆写入 | `user_id`、`memory_id` |

- 投递语义 `at-least-once`，消费端必须幂等（以 `event_id` 去重）。
- 死信：`x-dead-letter-exchange` 指向 `zxkap.dlx`，失败任务入 `admin.dlq` 供重放。

### 7.2 Webhook 约定

- 注册：`POST /openapi/v1/webhooks`，字段 `url`、`events`、`secret`、`description`。
- 投递：HTTP POST，`Content-Type: application/json`；Header `X-NKAP-Event-Id`、`X-NKAP-Signature: HMAC-SHA256(secret, body)`、`X-NKAP-Timestamp`。
- 重试：指数退避（1m/5m/30m/2h/6h），最多 5 次；最终失败进死信并告警。
- 幂等：载荷含 `event_id`，接收端按 `event_id` 去重；接收端需在 5s 内返回 2xx，否则视为失败。
