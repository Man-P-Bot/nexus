## 三、已冻结的关键决策（勿擅自变更）

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| D1 | Agent 编排 | LangGraph4j 状态图（Java 版 LangGraph） | 显式编排，可控可调试，契合 Java 栈 |
| D2 | 检索策略 | Lucene BM25 + pgvector 向量混合 → RRF → Rerank | 兼顾精确与语义，抑制幻觉 |
| D3 | 向量库 | pgvector 主（与业务库同库）/ Milvus 备 | 同库部署运维成本低，过滤检索满足需求 |
| D4 | 模型策略 | DeepSeek/Qwen 主力 + Ollama/vLLM 本地兜底（OpenAI 兼容接口） | 私有化 + 成本可控，用户自由配置 |
| D5 | 工具接入 | MCP 统一标准（Spring AI MCP）+ Function Calling 桥接 | 生态标准化 |
| D6 | 评估可观测 | Langfuse + Micrometer/Prometheus + 内建评估门禁 | 上线质量可量化 |
| D7 | 文档级 ACL 模型 | `grantee_type`（user/role/group）+ `grantee_id` + `permission`（read/download/delete） | 与 10《数据库设计》§5.2、04 需求 KB-008 一致，检索/引用共用同一权限上下文 |

> 变更任一决策须先更新 [项目基线与统一约定](../00-项目基线/项目基线与统一约定.md) 的「变更记录」，并通知交接方。

## 七、风险提示（开发阶段需重点关注）

1. **RAG 检索质量不达标** → 优先建立评估集，用指标驱动调优（见 14 风险登记册）。
2. **文档解析格式复杂** → MVP 先支持 PDF/Word，表格/图片 OCR 放 V1。
3. **权限模型复杂** → MVP 先实现「空间级 + 文档级 ACL」，标签权限放 V1。
4. **模型成本** → 设置 Token 预算与限流，评估小模型替代。
