# 17 给下一个 AI 的开发指引

> **这份文档是给接手本项目的下一个 AI 助手的操作手册。**
> 读完它，你就能从「设计完成」直接进入「可运行 MVP」。
> 请严格按 Step 0 → Step 5 顺序执行；每完成一步，更新 [15 任务记录](15-任务记录.md) 与本文档末尾的进度。
> **技术栈：Java 21 + Spring Boot 3（务必先读基线确认）。**

## Step 0 · 初始化开发环境（0.5 天）

1. 进入工作目录：`D:\homework\projects\nexus`
2. 初始化 Java 项目（Maven 或 Gradle，二选一）：
   - Maven：`mvn archetype:generate -DgroupId=com.nexus.nkap -DartifactId=nkap -Dversion=0.1.0 -DarchetypeArtifactId=maven-archetype-quickstart -DinteractiveMode=false`
   - 或直接手写 `pom.xml`，关键依赖：
     ```xml
     <parent>
         <groupId>org.springframework.boot</groupId>
         <artifactId>spring-boot-starter-parent</artifactId>
         <version>3.2.x</version>
     </parent>
     <!-- spring-boot-starter-webflux / -web / -data-jpa / -data-redis / -security
          spring-ai-starter-model-openai / langchain4j / langgraph4j
          org.postgresql:postgresql / vector / pgvector-java
          spring-boot-starter-amqp / minio / flyway-core
          micrometer-registry-prometheus / io.micrometer:tracing-bridge-brave -->
     ```
3. 创建目录骨架：
   ```
   zx-kap/
     src/main/java/com/zhixing/kap/
       KapApplication.java
       config/          # Spring 配置、Security、WebFlux、RabbitMQ
       common/         # 统一响应、错误码、工具类
       security/       # JWT/OIDC、鉴权过滤器
       modules/
         kb/           # 知识库管理
         ingestion/    # 文档处理管线
         retrieval/    # 检索引擎
         agent/        # Agent 编排(LangGraph4j)
         tools/        # 工具与 MCP
         memory/       # 会话与记忆
         citation/     # 引用溯源
         admin/        # 管理与可观测
         openapi/      # 开放平台
       domain/         # JPA/PO 实体
       mapper/ or repository/  # 数据访问
       api/            # REST/SSE 控制器
     src/main/resources/
       application.yml
       db/migration/   # Flyway SQL
     deployments/
       docker-compose.yml
   tests/
   ```
4. 编写 `application.yml`（PostgreSQL、Redis、RabbitMQ、MinIO、LLM API Key 配置占位）。
5. 编写 `docker-compose.yml`，启动 PostgreSQL 16（含 pgvector）、Redis 7、RabbitMQ、MinIO 本地实例。
6. 启用 Flyway 初始迁移，编写 `.gitignore`，`git init` 并提交首个 commit。

> 完成后更新任务记录：新增「T-011 项目骨架初始化 ✅」。

## Step 1 · 数据层与基础服务（1 天）

1. 按 [10 数据库设计](../03-系统设计/10-数据库设计.md) 的 ER 图，实现实体与 Flyway 迁移（MVP 至少 8 张表）：
   `tenant`、`space`、`document`、`document_version`、`chunk`、`conversation`、`message`、`api_key`。
2. 启用 pgvector 扩展，创建 `documents` 向量表或 collection（字段：`vector(1024)` + payload 过滤字段 `space_id`/`tenant_id`/`doc_id`/`chunk_id`）。
3. 配置 HikariCP 连接池、JPA/MyBatis 数据访问。
4. 实现统一响应结构、错误码、鉴权依赖（JWT + API Key，MVP 用 JWT）。
5. 实现健康检查接口，启动应用验证返回 200。

---

## Step 2 · 文档处理管线（1-2 天）

1. 实现 `ingestion` 模块：上传 → 解析 → 切分 → 向量化 → 入库。
2. MVP 支持格式：**PDF、Word(docx)、TXT、Markdown**（表格/图片 OCR 留 V1）。
3. 解析用 Apache Tika / PDFBox / POI；切分策略 `chunk_size=500`、`overlap=80`，优先按标题层级。
4. Embedding 用 bge-m3（TEI 本地或远端 API）；向量化后写入 pgvector。
5. 元数据写入 `document` / `chunk` 表。
6. 用 RabbitMQ + Spring Batch 做异步入库任务，失败可重试。
7. **验收**：上传一份 PDF，能在 pgvector 查到对应向量，文档状态变为 `ready`。

---

## Step 3 · 检索与 RAG 闭环（1-2 天）

1. 实现 `retrieval` 模块：
   - 查询改写：简单规则生成 1~3 个子查询（MVP 可先用单查询）。
   - 混合检索：Lucene BM25 + pgvector 向量，RRF 融合，取 Top-K（如 K=10）。
   - 重排：可选，MVP 可跳过 Rerank，用融合排序结果。
2. 实现 `citation`：为每个召回片段生成 `citation_id`，最终答案引用 `chunk_id` + 原文片段。
3. 实现 `memory`：会话表 + 消息表，短期记忆取最近 N 条消息（Redis 缓存）。
4. 实现 LLM 生成：Spring AI ChatClient，系统提示词要求「只依据给定资料回答，引用来源；无依据则说明」。
5. 实现 **SSE 流式问答**（Spring WebFlux `SseEmitter`），事件类型遵循 [11 接口设计](../03-系统设计/11-接口设计.md)：`meta` / `token` / `citation` / `done` / `error`。
6. **验收（MVP 闭环）**：前端或 curl 提问 → 流式返回带引用的答案，点击引用可跳到原文片段。

---

## Step 4 · Agent 编排与工具（2-3 天，可后置）

1. 按 [09 详细设计-RAG与Agent](../03-系统设计/09-详细设计-RAG与Agent.md) 用 **LangGraph4j** 实现状态图：
   `RETRIEVE → (是否需工具?) → TOOL_CALL / GENERATE → VALIDATE → END`。
2. 意图路由：判断问题是否需要调用工具（如查询业务数据、计算）。
3. 实现内置工具：`web_search`、`calculator`、`kb_search`（MVP 至少 2 个）。
4. 接入 MCP：用 Spring AI MCP SDK 注册 MCP Server，桥接 Function Calling。
5. 上下文工程：Token 预算管理，超限则压缩历史或截断。
6. **验收**：对「帮我算一下 X」或「查一下业务数据」类问题，Agent 能正确调用工具并整合结果。

---

## Step 5 · 权限、评估与前端（3-5 天，按优先级）

1. **权限（P1）**：文档级 ACL 注入检索链路——检索前按用户可见空间过滤 pgvector payload。
2. **评估（P1/P2）**：建立小型评估集（20~50 条问答），计算引用准确率、无依据回答率；接入 Langfuse 记录 trace。
3. **前端（P2）**：知识库上传页 + 对话问答页（可用 Vue/React，调用后端 REST + SSE）。
4. **部署（P2）**：完善 `docker-compose.yml`，编写 `README` 开发/部署说明。
5. **审计**：记录问答审计日志到 `audit_log` 表。

## 七、常见问题与应对

| 问题 | 应对 |
|---|---|
| 本地没 GPU，跑不了大模型 | 用 DeepSeek/Qwen OpenAI 兼容 API；或 Ollama/vLLM 跑 Qwen2.5 7B |
| pgvector 连不上 / 无向量列 | 确认 `CREATE EXTENSION vector;` 已执行；检查 Docker 网络与地址 |
| 检索结果差 | 优先调 chunk 策略与查询改写；建立评估集量化对比 |
| 权限漏过滤 | 检索链路**强制**注入过滤，禁止仅靠提示词约束 |
| 流式不生效 | 确认用 `SseEmitter` 且返回 `text/event-stream`；前端用 EventSource/fetch |
| 依赖版本冲突 | 锁定 Java 21 + Spring Boot 3.2.x，用 Maven/Gradle 管理，记录版本 |
| LangGraph4j 文档少 | 参考 LangGraph 官方概念（状态图/节点/边），Java 版 API 类似 |
