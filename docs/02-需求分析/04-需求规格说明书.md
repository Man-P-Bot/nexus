## 0. 文档说明

1. 本文档为「星枢 Nexus · 企业智能知识库与问答智能体平台（代号 NKAP）」需求阶段的核心交付物，定义系统「做什么」，不定义「怎么做」（实现细节见系统设计文档）。
2. 需求条目优先级采用 MoSCoW：**Must**（必须，MVP 不可缺失）/ **Should**（应该，重要但可延后）/ **Could**（可以，增强项）/ **Won't**（本期不做，仅登记约束）。
3. 需求条目标注落地阶段：**MVP**（最小可运行闭环）/ **V1**（首个完整版本）/ **V2**（规划版本）。
4. 每条需求均给出可测试的验收标准；无法量化的以「可通过演示/用例验证」表述。
5. 本文档不含代码，所有接口、字段名仅以英文小写下划线风格出现。
6. 技术细节引用基线冻结的 Java 技术栈组件（如 Spring WebFlux、pgvector、bge-m3、LangGraph4j），但需求条目以功能与验收为准，不涉及实现细节。

## 1. 需求概述与范围

### 1.1 建设目标

| 目标 | 量化指标 |
|---|---|
| 让员工快速获得可验证答案 | 员工在 2 个点击内获得「带原文引用、可验证」的问题答案 |
| 降低重复咨询 | 支持类岗位重复咨询量下降 30% |
| 首期覆盖 | ≥ 3 个业务域、≥ 1000 份文档、≥ 50 个 API 工具 |
| 回答质量 | RAG 回答引用准确率 ≥ 90%，无依据回答率 ≤ 5% |

### 1.2 需求范围

**范围内（In Scope）**

1. 知识库管理（kb）：空间、文档、版本、标签、批量导入、文档状态机、权限可见性。
2. 文档处理管线（ingestion）：多格式解析、图片 OCR、表格提取、自动切分、向量化、混合索引、增量更新、失败重试。
3. 检索引擎（retrieval）：查询改写、混合检索（Lucene BM25 + pgvector 向量）、重排、权限过滤、引用溯源。
4. Agent 编排（agent）：意图路由、工具调用、多智能体协同、人工审批。
5. 工具与 MCP（tools）：内置工具、MCP Server 接入、工具注册与鉴权。
6. 会话与记忆（memory）：多轮会话、短期/长期记忆、上下文压缩。
7. 引用与溯源（citation）：片段级引用、跳转、引用高亮、引用校验。
8. 管理与可观测（admin）：RAG 评估、审计日志、指标看板、反馈闭环、租户与配额。
9. 开放平台（openapi）：API Key、配额限流、Webhook。

**范围外（Out of Scope，本期不做）**

1. 企业业务系统的双向写回（仅支持只读工具调用与审批后写操作，Won't-V2）。
2. 多模态生成（图片/音视频生成），仅做图片 OCR 与表格理解。
3. 面向公众（C 端）的开放注册与公网自助服务。
4. 自研大模型训练与微调（仅接入已有模型，如 DeepSeek / Qwen / Ollama）。

### 1.3 目标用户

| 角色 | 标识 | 使用场景 |
|---|---|---|
| 平台管理员 | `admin` | 租户、模型、配额、系统配置 |
| 知识库管理员 | `kb_admin` | 创建空间、上传文档、配置权限与切分 |
| 普通员工 | `employee` | 对话问答、查看引用、反馈评价 |
| 开发者 | `developer` | 通过 OpenAPI 集成、管理 API Key |

### 2.2 文档处理管线（ingestion）

| 编号 | 名称 | 描述 | 优先级 | 阶段 | 验收标准 | 关联模块 |
|---|---|---|---|---|---|---|
| ING-001 | 多格式解析 | 基于 Apache Tika + Apache PDFBox + Apache POI 解析 PDF/Word/Excel/PPT/TXT/Markdown/HTML，输出结构化段落、标题层级与元数据。 | Must | MVP | 9 类常见格式解析成功率 ≥ 95%；解析保留标题层级；失败文件入失败队列并告警。 | ingestion, kb |
| ING-002 | 图片 OCR | 对扫描件、图片型 PDF、图片使用 Tesseract / PaddleOCR 做中文/英文文字识别。 | Must | V1 | 印刷体中文识别准确率 ≥ 90%；扫描件解析后文本可检索；OCR 结果标记来源为 OCR。 | ingestion |
| ING-003 | 表格提取 | 从 Excel/Word/PDF 中提取表格并结构化为 Markdown/键值对，保留行列关系。 | Should | MVP | 规则表格提取结构准确率 ≥ 85%；合并单元格可读；表格内容可参与检索与引用。 | ingestion, citation |
| ING-004 | 自动切分 | 按标题层级 + 长度 + 重叠窗口自动切分片段，保留片段所属章节与页码锚点。 | Must | MVP | 切分片段 ≤ 1024 token、重叠 ≤ 10%；片段不跨章节（可配置）；片段带 `chunk_id` 与锚点。 | ingestion, citation |
| ING-005 | 向量化与混合索引 | 使用 bge-m3（TEI 本地/远端）生成 Embedding 写入 PostgreSQL 16 + pgvector，同时以 Lucene BM25 建立稀疏索引。 | Must | MVP | 片段 Embedding 维度与 pgvector 索引一致；BM25 与向量索引均可命中；索引任务可观测。 | ingestion, retrieval |
| ING-006 | 增量更新 | 文档修改/新增仅重新处理受影响片段并更新索引，避免全量重建。 | Must | V1 | 单文档增量处理耗时 ≤ 全文处理 20%；增量后旧片段不可命中；版本切换正确。 | ingestion, kb |
| ING-007 | 失败重试 | 解析/向量化失败按指数退避重试，达到阈值进入死信队列并告警。 | Must | MVP | 瞬时失败自动重试 ≥ 3 次；最终失败记录可查、可手工重投；死信队列有告警。 | ingestion, admin |
| ING-008 | 处理任务调度与监控 | 基于 Spring AMQP（RabbitMQ 3.13）的异步任务队列，支持优先级、并发限制、任务状态查询与取消；批量任务可用 Spring Batch / Quartz 承载。 | Must | MVP | 任务状态实时可查；高优任务抢占；重复提交被去重；任务积压可告警。 | ingestion, admin |
| ING-009 | 解析质量报告 | 输出解析质量指标（空文本率、乱码率、表格/图片数、片段数）供管理员评估。 | Could | V1 | 每次解析生成质量报告；异常文档被标记；报告可在管理端查看。 | ingestion, admin |

### 2.3 检索引擎（retrieval）

| 编号 | 名称 | 描述 | 优先级 | 阶段 | 验收标准 | 关联模块 |
|---|---|---|---|---|---|---|
| RET-001 | 查询改写 | 将口语化问题改写为 1–5 个检索子查询，识别时间/指代/领域词，必要时拆分复合问题。 | Must | MVP | 改写结果可解释（保留原文与子查询）；常见口语问法改写后召回提升；改写不改变用户权限。 | retrieval, agent |
| RET-002 | 混合检索 | Lucene BM25 稀疏召回 + pgvector 向量稠密召回，按权重融合（如 RRF/加权），默认各取 Top-50 融合出 Top-20。 | Must | MVP | 单查询召回 P95 ≤ 500ms；混合召回显著优于单一通道；融合参数可配置。 | retrieval |
| RET-003 | 重排序 | 使用 bge-reranker（TEI 本地 / 远端 API）对 Top-N 做精排，输出最终 Top-K 送入上下文。 | Must | V1 | 精排 Top-K（默认 8）语义相关性提升；重排 P95 ≤ 800ms；无 Reranker 时降级为向量排序。 | retrieval |
| RET-004 | 权限过滤检索 | 检索前注入租户、空间、用户/组 ACL 过滤条件，pgvector 与 BM25 双通道均执行过滤。 | Must | MVP | 越权内容 0 命中；权限过滤后结果与 ACL 一致；过滤条件随会话用户实时计算。 | retrieval, kb |
| RET-005 | 引用溯源上下文组装 | 上下文按「片段 + 引用锚点」组装，每个片段携带 `doc_id`/`chunk_id`/页码/章节，供生成与引用使用。 | Must | MVP | 组装后的每个上下文片段均带可解析引用标识；无引用片段不得进入生成。 | retrieval, citation |
| RET-006 | 空结果兜底 | 检索无命中或命中过少时返回「未找到相关资料」并给出建议动作，不强行生成。 | Should | V1 | 空结果时不生成无依据答案；兜底话术可配置；触发空结果率可统计。 | retrieval, agent |
| RET-007 | 检索结果可解释 | 展示命中分数、命中通道、匹配片段摘要，供用户与评估分析。 | Should | V1 | 结果列表含分数与通道标签；分数异常（>1 或 <0）被拦截；可按分数排序查看。 | retrieval, admin |
| RET-008 | 查询缓存与限流 | 对相同（用户+问题+权限）查询做结果缓存，缓存不跨越权限边界。 | Could | V2 | 命中缓存时延迟显著下降；权限变化后缓存失效；缓存命中率可观测。 | retrieval, openapi |

### 2.4 Agent 编排（agent）

|---|---|---|---|---|---|---|

| AGT-004 | 人工审批 | 高风险工具调用（写操作、敏感数据导出）触发人工审批，审批通过后执行，全程留痕。 | Must | V1 | 未审批不执行；审批超时策略可配置；审批记录可审计。 | agent, tools, admin |
| AGT-005 | 会话内任务编排 | 支持在一次会话中发起多步任务、中断与继续、任务状态展示。 | Should | V1 | 任务可暂停/恢复；会话上下文保留；用户可查看任务进度。 | agent, memory |
| AGT-006 | 兜底与降级 | 模型超时、工具失败、检索异常时按策略降级（重试/换模型/转人工/返回兜底文案）。 | Must | V1 | 单点失败不导致整轮对话崩溃；降级路径可配置；降级事件入审计。 | agent, retrieval |

### 2.7 引用与溯源（citation）

| 编号 | 名称 | 描述 | 优先级 | 阶段 | 验收标准 | 关联模块 |
|---|---|---|---|---|---|---|
| CIT-001 | 片段级引用 | 答案中每个事实性陈述绑定到具体 `chunk_id`，形成片段级引用。 | Must | MVP | 带引用答案占比 ≥ 90%；每条引用可解析到唯一片段；无引用的事实性陈述被抑制。 | citation, retrieval |
| CIT-002 | 引用跳转 | 点击引用标记跳转到原文预览对应位置（页码/章节/高亮片段）。 | Must | MVP | 跳转 URL 可直达对应片段；跳转目标与权限校验一致；跳转延迟 P95 ≤ 2s。 | citation, kb |
| CIT-003 | 引用高亮 | 在原文预览中高亮当前引用片段，并支持多引用切换。 | Should | V1 | 高亮位置与引用标记一致；多引用可切换；高亮不影响原文可读性。 | citation, kb |
| CIT-004 | 引用校验与无依据抑制 | 生成后对引用与答案陈述做一致性校验，无依据内容改写或拒答。 | Must | V1 | 引用准确率 ≥ 90%；无依据回答率 ≤ 5%；校验失败答案标记原因。 | citation, agent, admin |
| CIT-005 | 引用样式与导出 | 支持引用编号/角标/脚注样式，导出答案时附引用来源列表。 | Could | V2 | 样式可配置；导出文件包含来源列表与链接；导出遵循文档权限。 | citation |

| ADM-003 | 指标看板 | 通过 Micrometer + Prometheus + Grafana 展示问答量、命中率、延迟、错误率、工具调用、存储用量。 | Must | V1 | 核心指标齐全且实时刷新；异常指标可告警；看板按角色可见性控制。 | admin |
| ADM-004 | 反馈闭环 | 用户对答案点赞/点踩并填写原因，反馈进入评估集与优化队列，闭环可追踪。 | Must | V1 | 反馈可提交、可查看处理状态；反馈样本进入评估集；处理结果可回写。 | admin, citation |
| ADM-005 | 租户与配额管理 | 管理租户、模型、API Key 配额、存储配额与并发上限。 | Must | MVP | 超配额行为被限流并提示；配额变更可审计；租户间数据严格隔离。 | admin, openapi |
| ADM-006 | 计费与成本 | 按模型调用、存储、工具调用统计成本并输出账单。 | Could | V2 | 成本可按租户/部门分摊；账单可导出；成本异常可告警。 | admin, openapi |

| NFR-011 | 兼容性 | 浏览器与开放协议 | 支持主流浏览器最近 2 个版本；REST / WebSocket / MCP | V1 |

## 5. 约束与假设

### 5.1 约束

| 编号 | 约束 | 说明 |
|---|---|---|
| CON-001 | 技术栈冻结 | 严格遵循基线技术栈（Java 21、Spring Boot 3.2+、Spring WebFlux、Spring Security 6、Spring AI 1.0、LangChain4j、LangGraph4j、PostgreSQL 16 + pgvector、Lucene BM25、bge-m3、bge-reranker、Redis 7、RabbitMQ 3.13、MinIO、WebFlux SseEmitter、MCP、Langfuse 等）。 |
| CON-002 | 私有化优先 | 核心模型与数据可完全离线部署，离线环境不得依赖外部 API（Ollama / vLLM 兜底）。 |
| CON-003 | 权限不可绕过 | 检索、预览、引用、导出全链路强制执行权限过滤。 |
| CON-004 | 可观测强制 | 每次 LLM 调用必须有 trace，每个 RAG 结果必须有评估分数。 |
| CON-005 | 命名与术语 | 接口、字段、模块命名遵循基线，中文首次出现写「中文（English）」。 |

### 5.2 假设

| 编号 | 假设 | 风险 |
|---|---|---|
| ASM-001 | 企业可提供 OIDC 统一身份源与角色映射 | 无 IdP 时需本地账号兜底 |
| ASM-002 | 首期文档以文本型 PDF/Word/Excel 为主 | 扫描件占比高会加大 OCR 成本 |
| ASM-003 | 业务系统可通过 MCP 或 REST 提供只读接口 | 无接口则工具调用能力受限 |
| ASM-004 | 私有化部署环境具备可用 GPU/推理资源 | 资源不足时模型延迟上升 |
| ASM-005 | 用户接受「无资料则拒答」的问答策略 | 过度拒答影响体验 |
